## Request budget and engineering implications
- DhanHQ v2 official documentation: quote API **1 request per second**, up to **1,000 instruments/request**; general data APIs 5 requests/second, up to 100,000/day. These are maximum published API ceilings, NOT measured safe BOT KING production rate.
- At proposed 15s equity + 15s index cadence, there are ~8 quote polls/minute (assuming two distinct quote requests) plus option/history/assessment. Whether quote budget is sustainable depends on Oracle collecting once per request type and deduplicating across clients. Avoid per-card requests.
- v2.3.128 currently still uses 60s equity, 60s index, 60s selected options, 180s Oracle assessment, 180s index history, 180s rest between 54-symbol scan passes, 10s local Top Five and 2s local Watchlist. The proposed fast rates are **NOT DEPLOYED**.
- 5m history cannot yield a new *completed* candle before the next 5m close; refreshing the full 54-symbol series more often generally wastes quota and may amplify HTTP429.
- Dhan error annexure distinguishes rate limit (DH-904 or data 805), expired token (DH-901 or 807), missing access (DH-902 or 806) and data errors. Never assume stale snapshot equals rate limit; verify Oracle ingestion/collector and sanitized endpoint status.
- Need Oracle read-only audit of collector cadence, age and quotes, index batch, selected chain/expiry and historical availability; no access to production was used in producing this inventory.

## Unified coordinator design / priority
1. One read-only **Oracle quote collector** for batch equity + indexes with separate priority, bounded by Dhan quote limits; persist last-good price and collection age. Never schedule N different consumers to contact Dhan.
2. One **Oracle option chain** collector for chosen underlying + listed expiry, own 3.25s pacing, 422/429 cooldown, cache listed expiries separately from strike chain.
3. One **Oracle candle collector** with completed-candle revision key (symbol/timeframe/latest completed timestamp), prioritize selected symbol, indexes, Top Five; batch pace 54 symbols without a fanout storm; persist last-good 30+ valid bars.
4. Independent derived processors: Scanner and Super Five react in ~2s locally to revisions; News slow TTL; Assessment OI cached and shared; Futures WAIT absent verifiable source.
5. One global **data refresh** button outside hours, cache-first and deduplicated; market-hours automatic 09:10–15:45 weekdays (plus holiday gate); never repaint static names/navigation; no real orders.
6. Instrument per source: `attempt_at`, `success_at`, `oracle_collected_at`, `exchange_time_verified`, `data_age`, `last_http_category`, `cooldown_until`, `cache_hit`, `request_count`, `consumer_count`, UI revision. Only after a healthy 20–30 minute open-session sample tune faster.

### Latest active source inspected (read-only)
- `src/main.py::refresh_watch_batch` uses async `asyncio.to_thread` for selected equities; prioritizes watchlist/paper positions; quote auto polling is subject to ~60s floor and cooldown.
- `src/main.py::watch_visible_tick` wakes every 2s while Watchlist visible. It computes per-visible-symbol 3m signals, signatures, age flags and rechecks each row. Even if price unchanged, signature computation can still occupy UI event loop; when signature differs it rebuilds `five_engine_chips`, assessment `note` and compact signal controls, invoking repeated `update()` calls. `fill_watch()` rebuilds all rows and calls `page.update()` for membership/search/navigation transitions; filtered-membership changes may invoke it.
- `src/main.py::refresh_mounted_data_sections` does not recreate the entire Dashboard/Scanner page on typical refresh, but rebuilds *all* registered dynamic sections for a target, even if only one value changes; this is section-delta not control/value-delta.
- `src/main.py::warm_selected_watch_three_minute_early` respects provider gap, 3 uncached requests per 180s, 30s floor, lifecycle/timeframe isolation; provider candle readiness cannot be equated with local paint frequency.
- `src/clone_v2_gateway.py::market_quotes` caps input at 73 names and validates source/freshness; `CloneDhanReadOnly` caps equity selection at 70 and performs no local rendering; quote_timestamp can be None, thus freshness is unverified.
- `src/clone_day2_apply_queue.py` is a **separate, not imported** synthetic prototype. Its bounded coalescing policy and 9 new offline tests are authored but NOT executed nor Android-wired. As authored it uses a sorted priority queue with repeated `list(self.pending).index(k)` (quadratic-ish ordering work for large queues), count-based budgets without measured frame elapsed time, and retained failing item retried on each tick. These need optimization/limits before any production integration. No measured RAM/CPU/frame figures have been obtained.
- Therefore **confirmed architectural improvement opportunities** are repeated signal/signature work on tick, repeated per-child updates, broad section factory rebuilds, and lack of a single measured app-side apply scheduler. **Root-cause of prior UI freeze remains unproven** without timestamped phone traces; Dhan/Oracle ingress latency also remains unproven.

### Target concrete building, distinct layers
1. **Ingress / verify:** only Dhan read-only via Oracle secured shared gateway; stamp receiving time separately from Dhan source time. Validate symbol, source, timeframe, expiry, finite price/valid OHLC and generation.
2. **Bounded stock:** immutable last-good snapshot by (generation,symbol,stream,timeframe,expiry); bounded history ring-buffer, freshness state HIST/STALE/WAIT; avoid stacking identical quote revisions. Preserve completed candle history until actual correction/revision, apply ongoing candle delta by key and monotonic sequence. Do not drop obligatory candle-close evidence because of price coalescing.
3. **Compute lane:** off-UI expensive filter/candle calculation, memoized by input revision, no recalculation if same signature; five existing filters only. Invalidate correct dependent widgets when source/filter/timeframe changes.
4. **Apply queue:** independent per-screen priorities: visible Watchlist/Dashboard/Scanner first, offscreen deferred; bounded latest-value coalescing, generations guard, per-frame time budget based on phone measured jank/CPU/memory, starvation prevention and exponential error backoff. Keep UI interactive during large bootstrap; never use one global lock across slow network/compute.
5. **Mounted delta renderer:** fixed row/card/control identity, update only changed fields, active candle tail and affected chart bars; do not remount whole page/scroll/chart for each tick. Explicit separate structural rebuild only on navigation, watchlist membership/search or feature layout change, with cached rows.
6. **Diagnostics / Help Doctor:** span ID trace of RECEIVE → VALIDATE → CACHE → COMPUTE → QUEUE → APPLY → RENDER; per-step elapsed ms, queued backlog, oldest pending age, last applied revision, local memory/CPU/jank metrics (privacy-safe); error classes NETWORK/PROVIDER_429/VALIDATION/STALE/TIMEFRAME/QUEUE_FULL/COMPUTE/UI_APPLY/DEVICE_PRESSURE, with affected symbol, source validity and safe recovery instructions. Do not log keys or quote payload contents.
7. **Adaptive performance policy:** no premature promise of 1s or 2s full Watchlist. Start with deliberately small UI work slices and measure 5/20/40/70-symbol synthetic loads; determine whether visible-value apply meets 20–25s *whole cold bootstrap* goal, while UI remains navigable. Later compare 10/30/50 Mbps with RTT and loss profiles and 1–4 devices. Do not use 20–25 seconds as a fixed provider or candle update interval. More frequent incremental quote changes may apply in milliseconds if budget allows.

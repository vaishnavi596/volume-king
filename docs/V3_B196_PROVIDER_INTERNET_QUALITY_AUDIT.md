# BOT KING V3 B196 — Provider, internet and quality prebuild audit
Date: 2026-11-21. Branch: `pilot/v1-pure-original-clone-phone-20261120`.
Scope: source + GitHub Actions evidence ONLY. No physical phone, live network/Dhan login, Oracle runtime verification, APK/signing or production changes. An offline unit PASS alone does not prove mobile Internet delivery.

## Result: RELEASE HOLD — NOT READY FOR APK

### Confirmed code and connection routes
1. **V3 phone startup/UI:** `src/main.py` normalizes stored `prefs["source"]` to Dhan; the visible provider dropdowns are Dhan-only, and `source_change()` clamps injected dropdown selections to Dhan. This does NOT, by itself, prove all transport paths are absent.
2. **Legacy Yahoo transport:** `src/main.py` still defines `get_yahoo()` issuing HTTPS requests to `query1.finance.yahoo.com` then `query2.finance.yahoo.com`. `fetch_market_data_uncached()` formerly dispatched on `selected=="Yahoo Finance"`. The B196 guard now rejects **all non-Dhan selections prior to that dispatch**, even if preferences are corrupted at runtime. Source commit `f3527c130a41a318ce109f60d1d962a0d11c6d11`. New explicit no-HTTP test in `tests/test_market_feed.py`, commit `19d6880585380a36b2c6f3ac59f2740942270e68`. The legacy function and hard-coded Yahoo host have NOT YET been removed; do not describe the app as free of all Yahoo code.
3. **Legacy Angel One:** `src/market_feed.py` defines read-only Angel adapter, broker HTTP and separate IP-detection calls (including `api.ipify.org`). `src/server_feed.py` defines `ServerAngelFeed`; `src/main.py` still constructs an instance and carries its old branch. The B196 hard boundary blocks network dispatch from `fetch_market_data_uncached()` for non-Dhan, but independent Angel integration/callback paths need full reachability analysis before physical deletion.
4. **Separate offline router:** `backend/provider_router.py` and `backend/provider_gateway.py` explicitly support Yahoo fallback and Angel provider. Their own docs say offline-preparation and no live provider network, and `src/main.py` does not call `choose_source` or `create_provider_app`. Deployment reachability not verified. DO NOT treat a green test of this legacy router as proof of Dhan-only architecture, and do not delete routes until deployment references are checked.
5. **Authorized Dhan pipe:** `src/server_feed.py` uses direct HTTPS requests and timeouts; `src/clone_v2_gateway.py` uses an independent clone gateway and checks protocol/authentication/read-only status. Do not rewrite/merge the two paths without an endpoint and login contract audit. Oracle runtime endpoint reachability, actual Dhan permissions, exchange quote timestamps, and 401/403/429 behavior are NOT validated by this static inspection.
6. **Non-market Internet:** `src/main.py::fetch_news` issues HTTPS RSS to BBC News Business or Google News RSS (timeout 8s, bounded payload); outbound RSS is not Dhan market data and is context-only/no independent trading vote. Links are HTTPS checked, but external network success and availability are NOT established. TradingView chart JS is bundled in app; examine embedded WebView/bootstrap request paths separately before asserting offline-only chart load.
7. **Cache boundary:** local snapshots, rankings and candle history must retain provenance and timeframe/generation; old Yahoo/Angel snapshots cannot be promoted to Dhan live signals. Never infer LTP live freshness from historical candle timestamps.
8. **Remaining latest full-regression failures:** [No-APK Run 44933612063](https://github.com/vaishnavi596/volume-king/actions/runs/44933612063) ran 1527 tests: **3 failures + 1 error**. Exact cases: `test_candle_analysis_survives_news_failure` (old Yahoo fixture returns before scan timestamp); `test_historical_strength_widget_retains_direction_with_historical_label` (old Yahoo historical evidence blocked); `test_stale_candles_do_not_claim_sideways_or_live_signal` (implementation reports `Completed candles are stale`, not literal `too old`; bias is WAIT); `test_superseded_scan_cannot_publish` (legacy async test expects restart on an unauthenticated Dhan scan). Distinguish changed contract from true runtime bug; do not weaken privacy/freshness/security gates to satisfy old fixtures.
9. **Existing quality tests reviewed:** `tests/test_dhan_only_provider_selection.py`, `test_dhan_only_startup.py`, `test_provider_cache_boundary.py`, `test_provider_router.py`, `test_provider_gateway.py`, `test_v3_news_repair_wiring.py`, `test_v3_full_phone_feature_gate.py`, `test_v3_max_feature_audit.py`, prior full offline gate logs, and the V3 master journal. These tests mix current contract with intentionally obsolete provider features, so passing them does not alone certify network independence.

## Required before any signed APK
- Pass test for injected legacy preference causing **zero Yahoo/Angel HTTP requests**, plus startup/source-change migration, without editing V1/Oracle.
- Reconcile or remove unreachable Yahoo/Angel source and offline provider fallback only after mapping deployment references, preserving provenance and compatibility.
- Confirm Dhan-only Scanner 1m/3m/5m, Dashboard 1m, Watchlist 3m, valid quote and candle timestamp/status, rate-limit/cooldown, and offline/after-hours fail-closed.
- Run targeted CI then complete offline regression **PASS**, with no suppressed failed tests; recheck changed files only.
- Independently validate authenticated Dhan quote/candle/option paths and RSS timeout/recovery on a device before calling real network integration complete.
- Only then initiate separate signed V3 APK build. Verify artifact existence and run ID; paper-only, no live orders.

## Quality verdict
**Static code audit incomplete for full reachability; real Internet/connectivity unverified; last full regression FAIL.** No claims of release readiness. This report is a release blocker, not evidence of a finished app.

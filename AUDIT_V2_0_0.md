# BOT KING 2.0.0 — Paper bot and interface audit

Implemented: Settings-only language/data selectors; compact source captions elsewhere; removed visible master save footers; field auto-save preserves last valid values and excludes credentials. Charts reuse the native view within the active scanner context, show cached history first, initially display 300 candles with More history, share short-lived request results, and push data changes instead of reloading HTML.

Paper trading: side-correct BUY/SELL SL and targets; Cash shares versus Options lots; expiry and finite positive value checks; manual contract confirmation; notional/capital and rupee/percentage planned-risk limits; detailed plan preview; Start/Pause/Stop; manual-tick bounded averaging, re-entry cooldown, partial whole-unit profit taking and favorable-only trailing; explicit exit prices/charges and signed realized P&L. Unknown exits stay unknown and block automatic paper re-entry. App background pauses the manual engine. Restart starts Stopped. Stop does not close an open position; EXIT remains available with emergency stop.

Validation: 97 offline unit/UI/persistence regression tests passed with Flet 0.25.2. Python source compilation passed. Tests include SELL levels/net P&L, invalid exits preserving positions, unknown exit journal values, capital/risk caps, cash/index rejection, manual confirmation, strategy limits, SL precedence over averaging, partial quantities, trailing monotonicity, pause/restart, re-entry cooldown, emergency-stop exits, auto-save, selector location, chart-view reuse and ready acknowledgement.

Limitations: No real broker order submission, broker fill reconciliation, streaming execution, server automation, push delivery, unattended lock-screen execution, or broker-side protection. Angel One integration remains read-only. Yahoo availability/freshness is source-dependent and does not provide verified NSE option chains. Notional is not margin and planned-stop risk is not a maximum-loss guarantee. Paper partial P&L excludes charges; final exit supports supplied charges. Square-off time remains a saved preference. Android install/device performance and native WebView behavior require on-device validation after packaging. No claim of guaranteed seamless upgrades across differing signing certificates.
